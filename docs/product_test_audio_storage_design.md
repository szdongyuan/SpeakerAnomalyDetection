# 产品测试音频保存设计

## 1. 目标

产品测试模式支持多个工况分别绑定测试队列。每次录音应能够追溯到当次产品型号、条码和工况，同时保持现有单配置及正反转项目的保存行为不变。

本文档只描述已实现的手动产品工况测试与音频保存逻辑。真实硬件状态报文匹配不在当前实现范围内。

## 2. 当前测试流程

当前阶段通过主界面的测试按钮逐次执行产品测试配置中的工况：

1. 按 `sub_configs` 的配置顺序取得当前工况。
2. 根据当前工况的 `test_queue` 加载测试队列。
3. 使用测试队列中的采集时长和分析配置开始录音。
4. 录音开始前保存当前工况上下文，录音完成后才推进到下一工况。
5. 每次点击只执行一个工况；全部工况执行后，下一轮重新从第一个工况开始。

`trigger_state` 保留在产品测试配置中，供后续真实硬件接入使用。当前手动演示流程不校验硬件状态报文。

## 3. 保存目录

产品工况录音按产品型号分目录保存：

```text
audio_data/stored_data/
└─ S004-1/
   ├─ not_labeled/
   ├─ OK/
   └─ NG/
```

产品型号为空时使用 `unspecified_model`：

```text
audio_data/stored_data/unspecified_model/not_labeled/
```

型号作为目录名时会替换 Windows 文件系统不允许的字符。旧单配置和正反转模式继续使用原来的扁平目录：

```text
audio_data/stored_data/not_labeled/
audio_data/stored_data/OK/
audio_data/stored_data/NG/
```

## 4. WAV 文件名

产品工况录音使用以下顺序：

```text
时间_条码_型号_工况_MAC地址.wav
```

示例：

```text
2026-08-04-14-32-15_BCSN240727018_S004-1_6000_rpm_107C610BB999.wav
```

条码为空时省略条码字段：

```text
2026-08-04-14-32-15_S004-1_7000_rpm_107C610BB999.wav
```

工况字段来自当前子配置的 `condition_name`，不增加重复的文件后缀配置。文件名组件中的空白及 Windows 非法字符统一替换为下划线。

旧单配置及正反转模式保持原文件名顺序，不进行迁移或重命名。

## 5. 数据库记录

WAV writer 使用生成后的完整嵌套路径创建文件。录音完成后，现有 `RecordingManager.save_signal_info_to_db()` 将相对于应用目录的文件路径写入 `audio_data_table`。

数据库结构不修改。音频管理界面继续从数据库记录加载文件；转速筛选从 WAV 文件名中识别带有 `rpm` 标记的工况名称。

## 6. 人工标记

人工点击 OK 或 NG 时继续使用现有 `FileOps.move_wav_to_dir()` 逻辑，不新增产品型号目录保留规则。

例如：

```text
标记前：audio_data/stored_data/S004-1/not_labeled/example.wav
标记 OK 后：audio_data/stored_data/OK/example.wav
```

文件移动成功后，现有流程同步更新数据库中的标签和文件路径。若数据库更新失败，现有回滚逻辑会把文件移入原标签对应的全局目录；该逻辑不会恢复产品型号子目录。

## 7. 兼容性边界

- 不修改产品测试配置 JSON 结构。
- 不修改工况顺序、测试队列绑定和录音时长读取逻辑。
- 不修改数据库表结构。
- 不修改旧单配置及正反转录音目录和文件名。
- 不实现真实 GPIO 或串口状态匹配。
- 后续硬件触发应复用当前工况录音、分析和保存入口，只替换手动触发来源。

## 8. 验证范围

自动化检查覆盖：

- 产品工况文件名字段顺序。
- 条码为空的文件名。
- Windows 非法路径字符处理。
- 按型号生成保存目录。
- 型号为空时使用 `unspecified_model`。
- 旧模式目录和文件名保持不变。
- `get_recorded_info()` 生成的路径及元信息一致。
- 人工标记继续移动到原有全局 OK/NG 目录。
- 音频管理界面能够从新文件名识别带 `rpm` 的工况。

当前验证不包含真实声卡、真实串口模块和生产数据库的现场联调。
