# 原始音频 CSV 导出后压缩为 ZIP

日期：2026-09-23。设计方向、命名修订及本文已由用户确认；独立规格复审已通过，进入实施计划。

## 1. 目标与已确认行为

现有产品录音在独立 CSV 子进程中，从已完成的 WAV 导出全采样 CSV。新增同进程后续压缩：每份 CSV 对应一个 ZIP，正常完成后只保留 ZIP；压缩失败时保留完整 CSV。WAV 不因压缩被删除或改写。

- 使用现有“WAV + CSV”导出选择，不增加独立压缩开关；显示文字说明 CSV 以 ZIP 保存。
- 新录音自动执行；不扫描、批量压缩或删除历史 CSV，不修改分析结果 CSV 的输出。
- ZIP 与当前 CSV 同目录，在完整 CSV 文件名后追加 `.zip`，例如 `audio/raw_csv/example.csv` → `audio/raw_csv/example.csv.zip`；其中恰有一个 `example.csv`，不带绝对路径或额外目录。
- CSV 仍完整落盘，再压缩。压缩文件完成、校验及原子发布成功后才删除 CSV。
- ZIP 已成功但 CSV 删除失败：保留两者，报告 ZIP 成功并提示 CSV 清理失败，不伪装成完全成功，也不撤销 ZIP。
- 导出、压缩、校验、清理整体占用一个任务名额，总容量仍为 16；任务资源释放后才归还。退出继续异步等待整个任务完成。

## 2. 当前实现与方案选择

`base/raw_audio_csv_exporter.py` 使用 float32 分块读取 WAV，按固定数值格式写 UTF-8 BOM、LF CSV，flush/fsync/close 后同目录 replace。`base/raw_audio_csv_worker.py` 串行执行，`RawAudioCsvService` 维护单个常驻 spawn worker 和父进程 FIFO。当前协议、账本及临时文件回收仅管理 WAV、CSV 和一份 CSV 临时文件；成功结果的路径与字节数也指向 CSV。

`SequenceWidgetRawCsvOpsMixin` 在提交前登记 CSV 归属；轮次文件登记当前排除 `.zip`，删除摘要也按扩展名区分。归档删除、轮次清理、重置、移动以及正常退出均使用同一个 CSV 服务协调资源。

| 方案 | 权衡 | 选择 |
| --- | --- | --- |
| 同一个 worker 先 CSV 后 ZIP | 保留失败回退 CSV，复用 FIFO/关闭逻辑；单任务变长 | 采用 |
| 另建压缩 worker/队列 | 能并行，但增加容量统计、磁盘及 CPU 竞争 | 不采用 |
| CSV 直接写入 ZIP | 减少中间文件，但压缩失败无法保留完整 CSV | 不采用 |

压缩采用标准库 `zipfile` 的 DEFLATE，压缩级别 1，优先减少额外 CPU 时间；支持 ZIP64。不承诺固定压缩率或导出提速。压缩与完整校验会增加耗时和临时磁盘占用，因此可能更早触及 16 个名额。

## 3. 数据流程及原子性

1. 沿用录音前预留、WAV 完成后提交的过程，冻结原始归属和 CSV 路径。用统一的纯路径转换在完整 CSV 路径后追加 `.zip`，派生同目录 `example.csv.zip`；不得替换掉 `.csv` 后缀。
2. worker 调用现有 CSV exporter，完成 CSV 的原子发布并关闭全部导出句柄。CSV 字节内容、精度和帧数不变。
3. 在 ZIP 目标目录排他创建本任务的 ZIP 临时文件；以有界二进制块读取刚发布的 CSV，写入唯一成员。读取过程中计算原始字节数与 SHA-256，不整文件读入内存。
4. 完成 ZIP 中央目录并关闭写入器，flush/fsync/close 底层输出。重新打开临时 ZIP，检查唯一成员名称、未压缩字节数；分块完整读取该成员到 EOF，触发 CRC 检查，并核对 SHA-256 与刚才读入的 CSV 字节一致。校验不向磁盘解压。
5. 校验读取句柄关闭后，同目录 `os.replace` 发布目标 ZIP。旧 ZIP 在此之前保持不变。取得输出尺寸等成功结果所需信息应在删除 CSV 前完成；发布后诊断失败不能导致清除有效 ZIP。
6. 仅删除本任务刚发布、身份仍匹配的 CSV；不扫描目录、不删除邻居文件。CSV 不存在可视为已清理；身份变化或删除被拒绝则作为清理警告保留现状。
7. 所有句柄关闭、清理结果确定后返回成功或带警告的成功；父进程完成一次 terminal/released，恢复一个名额。

整个过程的路径许可防止本应用内覆盖、删除或移动。对外部程序修改不提供跨程序锁保证；发现 CSV 身份或状态改变时停止压缩或保留 CSV 并告警，不猜测文件归属。发布最终 ZIP 与删除 CSV 不是同一个文件系统事务：两步之间崩溃允许留下两份完整文件，不允许为追求“只留 ZIP”而先删 CSV。

## 4. 组件与协议边界

- 保留 `export_raw_audio_csv` 的纯 CSV API 和默认行为；既有直接调用者及 CSV 格式基线继续可用。新增小型 ZIP 打包组件，worker 负责编排两个阶段，不能把压缩加入 GUI 或另起线程队列。
- `CsvExportRequest.csv_path` 继续表示中间及失败回退 CSV，统一派生 ZIP 路径。账本在规范化后登记 WAV、CSV、ZIP 三个路径，拒绝别名冲突、空路径或与源文件相同的目标。
- 扩展内部命令以传递两份精确临时路径（CSV、ZIP）；父进程在派发前生成并登记。两者分别排他创建，worker 分别发送含 task_id、generation、路径及文件身份的所有权确认。监督器从单临时路径状态改为本任务的有限映射，不接纳任意额外路径。
- 扩展内部结果，明确区分 CSV 路径与最终 ZIP 路径、CSV 未压缩字节数和 ZIP 字节数、CSV 是否保留及清理警告。不得把 `.zip` 悄悄塞进语义仍为 CSV 的结果字段；既有诊断工具同步更新字段解释。
- IPC 协议版本递增，父子进程一起升级；握手/消息处理仍核对版本、PID、task_id、generation 和预期目标路径。内部旧 worker 消息不兼容时明确失败，不做混合版本兼容层。
- 普通成功和“ZIP 已保存但 CSV 清理失败”都属于保存结果成功；后者必须携带可展示的警告。服务不能仅在 `CsvFailure` 上采集清理诊断，带警告成功也传入 released 记录。
- 成功必须发生在校验、发布、CSV 清理尝试与资源关闭之后；CSV 导出完毕不是整个任务的终点。GUI 成功日志指向实际 ZIP，清理警告每任务最多提示一次，不能让重复/迟到事件影响当前轮次。

## 5. 文件归属、清理和关闭

- queued 至 released 占用 WAV、CSV、ZIP。预留期间保留现有录音路径许可；提交时原子交接并加入两个输出路径。压缩及校验期间不能提前归还名额或开放文件修改。
- 在任务可被派发之前，把 CSV 与 ZIP 都登记到原录音记录的预期原始数据文件集合；即使压缩失败、CSV 删除失败或窗口已切换，仍有精确路径可供后续用户清理。
- 轮次登记仅把本次原始 CSV 对应 ZIP 纳入原始数据类别，不把任意 `.zip` 全局当作录音输出。原有分析 CSV、图片和报告的类别及删除边界不变。
- 删除摘要针对实际存在的文件计数。只有 ZIP 时计一份原始数据文件；回退 CSV 时计一份；清理失败两者都有时明确计两份实际文件，不把不存在的预期 CSV 计为成功保存。
- 归档删除、异常轮次延迟清理、同路径重录和实际移动文件的入口，修改许可覆盖对应 WAV/CSV/ZIP。延迟清理继续等待录音及 CSV 两种占用释放并保留优先权，不取消在途 ZIP、不跨轮次或扩大删除范围。
- 现有只保存 WAV/校准行为、OK/NG 数据库标注、满额需重新触发策略不变。
- 应用/可见窗口关闭异步等待已接纳任务的全部阶段，无 GUI join、文件扫描、同步压缩或 `processEvents` 等待循环。关闭提示覆盖“保存/压缩原始 CSV”。不增加导出或压缩超时，不强杀正常慢任务；现有 ready 与空闲退出超时沿用。

## 6. 失败语义

下表的“新文件”指本次任务生成的文件；“旧文件”指本次任务开始前，同一个完整目标路径上已经存在的同名文件，不指上一档录音。正常每档录音文件名不同，没有同名旧文件时，旧文件保护条款不涉及其他录音。ZIP 临时文件只属于本次任务，尚不是正式发布的 `example.csv.zip`。

| 失败位置 | 文件状态与用户结果 |
| --- | --- |
| 原 CSV 导出失败 | WAV 保留；沿用原 CSV 失败行为，不压缩旧 CSV |
| ZIP 创建、写入、fsync 或校验失败 | 新 CSV 保留，旧 ZIP 不动；清理本任务 ZIP 临时文件；提示 CSV 已保存、ZIP 失败及原因 |
| ZIP replace 失败 | CSV 和旧 ZIP 保留；不报告 ZIP 成功；回收本任务临时文件 |
| ZIP 发布成功、CSV 删除失败/身份不符 | ZIP 保留；保留剩余 CSV，成功带清理警告；句柄关闭后释放容量 |
| 临时文件清理失败 | 记录精确残留及异常；不得删除旁边文件；确认资源关闭后允许释放容量 |
| worker 突然退出/终态消息丢失 | 结果未确认；保留全部最终 CSV/ZIP；不凭文件存在宣称成功，不自动重试或自动删除 CSV |

监督器仅在 worker 死亡已确认后，按已确认所有权和一致文件身份逐个回收 CSV/ZIP 临时文件；没有确认、身份不符或 reparse 文件均保留并诊断。最终 CSV、最终 ZIP 永不作为异常回收对象。死亡未确认时保持许可，不启动第二个 worker。普通任务异常后的 worker 复用、启动失败策略沿用现有实现。

错误显示区分“CSV 导出失败”“CSV 已保存但 ZIP 压缩失败”“ZIP 已保存但 CSV 清理失败”，给出可定位的路径和原因；不得将它们变成录音或分析失败，也不得静默回退到主进程执行。

## 7. Compatibility / Migration

- Backward compatibility: partial。
- Protected surfaces: WAV 内容及路径；解压后的 CSV 逐字节格式；物理通道/时间列/精度；既有配置键 `export_raw_audio_csv`；数据库结构；纯 CSV exporter API；16 容量准入、FIFO、归属和关闭约束。
- Allowed breakage: 新的应用级原始 CSV 导出，正常最终产物从 `.csv` 改为 `.csv.zip`，外部直接读取 CSV 的流程需先解压；内部进程协议和内部结果结构一起更新。
- Migration strategy: none。旧配置选中 CSV 的项目自动使用 ZIP 保存新录音；默认关闭的仍关闭。历史 CSV 不迁移，旧 CSV 和新 ZIP 的既有用户删除流程都受支持。不增加历史扫描、自动解压、数据库迁移或额外设置。

配置选项和相关保存提示说明“WAV + CSV（ZIP 压缩）”，保留现有配置键和语义范围。容量提示继续表达 16 份任务，不能把 CSV 完成而 ZIP 尚未完成解释为名额空闲。

## 8. 诊断与验收

### 8.1 计时与资源

新增 worker 内部 CSV 导出、ZIP 写入、完整校验、ZIP 发布、CSV 清理及任务总耗时；保留父进程排队与 Qt 投递耗时独立统计。记录未压缩/压缩字节数、压缩率和警告，使用同进程单调时钟，不逐块发 GUI 事件或无界日志。完整校验的额外读取明确计入任务耗时。

### 8.2 自动化功能

1. 单/双/非连续通道、零帧、跨块、中文空格路径：ZIP 文件名为完整 CSV 文件名追加 `.zip`（`example.csv.zip`），唯一成员仍为原 CSV 文件名（`example.csv`）；覆盖带多个点的文件名，确保不丢失 `.csv` 后缀。解压字节与纯 CSV exporter 完全相同，源 WAV 不变；正常成功无最终 CSV 和任务临时文件。
2. 验证真正 DEFLATE 和 ZIP64 的写入配置；大成员支持不能仅凭微型 ZIP 成功宣称通过。拒绝意外多成员、错误名称、截断/CRC 错误、字节数或 SHA 不一致；确认失败保留 CSV。
3. 对创建/读写/fsync/校验/replace/删除注入异常；旧 ZIP 仅成功发布后替换，ZIP 失败保留 CSV，CSV 删除失败产生带警告成功，精确临时文件回收不触碰邻居。
4. 实际 spawn 顺序处理两个任务、同一健康 PID 复用；暂停在压缩/校验时验证一个 active + 十四个 queued + 一个 reserved 达到 16，第十七次拒绝，GUI timer 继续运行，完成只释放一个名额。
5. 终态丢失、两份临时文件所有权确认交错、错误 generation/PID/路径、已发布 ZIP 后退出：一次终态/释放，保留最终文件，未确认临时文件不删，无资源泄漏/第二个 worker。
6. ZIP 所有权覆盖归档删除、旧轮次延迟清理、重置/移动、CSV 回退和 ZIP+CSV 双文件警告；删除摘要按实际存在文件计数，不将其他 ZIP 纳入原始数据。
7. 主/子窗口异步关闭等待压缩、校验及清理；WAV-only/校准、自动分析和配置读取不受影响；提示/日志路径正确，重复通知不重复弹窗。
8. 纯 exporter 旧测试继续通过。更新 benchmark 和显式启动诊断，分别核对 ZIP 外部尺寸与成员 CSV 内容；源码两个入口检查与冻结产物检查分开报告。

### 8.3 完整数据和并发

- 使用现有已核对的 600 秒 WAV 和 CSV 内容基线，通过 ZIP 成员流式计算行数、字节数、SHA；要求 26,460,000 数据行、1,162,232,136 未压缩字节、SHA-256 `facb5196b26f7ac36fdb470fe8850a89106fd94b7602164b40c24eeba38e5b65`。不复制造新的旧 CSV 基线、不为校验落地解压大文件。
- 同机对照现有纯 CSV 子进程与“CSV + ZIP + 校验”，记录新增各阶段耗时、压缩尺寸和采样内存；选定同一代表性 fixture、200 工况 GUI、相同分析与模拟下一档录音负载，每组至少三次并交错，完整 WAV 各至少一次。
- 正确性为硬门槛；代表性 GUI 完成时间中位数及实际采集启动延迟中位数，各不高于纯 CSV 子进程对照的 110% 加 100ms，Qt 50ms 心跳每次 p95 的中位数不恶化超过 20ms。计时原始值和采样条件必须保留。完整场景报告方向与实际数值，不以小数据替代。
- 测试需证明分块读写与校验，不向 IPC 或内存传整个 CSV。报告采样内存峰值和采样间隔；不把有限采样说成进程生命周期绝对峰值。
- 不保证任务总时间更短、固定压缩率或相同容量下不积压；发生性能回归先定位新增阶段，不扩大到录音、历史表格或分析重构。
- 模拟录音不能证明真实设备无丢帧，源码入口不能证明冻结运行成功。实际发布环境不可用时保留对应未验证项及原因，不重复把既有打包故障当作本次通过依据。

## 9. 实现约束与非目标

- 只在带语义的边界抛异常：路径/协议错误、压缩校验失败、发布失败。底层文件异常保留原因；worker 的每任务边界统一归一化。CSV 删除作为单独已成功保存后的清理边界处理。
- 禁止无依据的广泛捕获、静默忽略、重复包装掩盖原异常、失败后自动重压或回退 GUI 线程；日志失败不得破坏文件安全与释放。
- 使用实例或任务局部状态。禁止单次使用的模块全局常量，除非它属于文件格式、IPC/CLI、序列化状态等稳定边界；跨模块/测试稳定共用的协议常量放 `consts`。无全局 singleton 或模块导入时启动进程。
- 不增加并行压缩 worker、持久化任务恢复、历史文件迁移、ZIP 浏览器、密码/加密、归档分卷或通用压缩服务；不更改采样率、精度、物理通道与录音时长。
