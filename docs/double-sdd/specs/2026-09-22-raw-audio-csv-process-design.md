# 原始音频 CSV 独立进程导出设计

日期：2026-09-22。设计基点：`dc9cf104e80179bc176c1dbc7fa57b36e0d69ce1`。

设计方案已获用户同意；用户将任务总容量明确设为 16。本文已通过独立文档审查，用户审阅并确认继续进入实施计划。本文不授权实现。

## 1. 目标与范围

把已完成 WAV 的原始 CSV 导出，从主进程内的后台线程迁移到专用子进程，减少逐样本 Python 格式化对 GUI、录音准备和自动分析入队的干扰。保持完整原始数据及现有文件格式。

本次包括：一个常驻导出子进程、有界任务管理、录音前容量预留、Qt 结果投递、文件占用保护、异常退出处理、正常关闭，以及必要的分段计时和验证。

不包括：历史表格/约 200 个工况控件刷新优化、间隔调度器改造、分析算法优化、CSV 压缩或降采样、提高 CSV 并行度、持久化导出队列、跨应用重启恢复任务、手动补导出新功能。不能承诺消除全部等待，也不能承诺 CSV 本身总导出耗时显著缩短。

## 2. 已核对的现状与证据

- `base/raw_audio_csv_exporter.py` 从已完成 WAV 按 8192 帧读取 float32，逐样本格式化；UTF-8 BOM，LF 换行，首列 `time_s`，随后为物理通道 `CH{编号+1}`；时间 `.9f`、数值 `.9g`；全部样本输出；同目录临时文件 flush、fsync、close 后 os.replace 发布。失败时清理自身临时文件，保留已存在的目标文件。
- `SequenceWidgetStreamingOpsMixin._schedule_raw_audio_csv_export` 每次建立一个非 daemon 线程，没有任务容量上限；先登记本轮输出归属，再启动线程。成功/失败通过 Qt 信号投递。普通录音完成流程不等待 CSV 完成。
- `SequenceWidget` 初始化线程集合和锁；`_wait_for_raw_audio_csv_exports` 当前同步 join。主窗口退出、可见 sequence 窗口关闭调用它；初始化时隐藏 sequence 窗口的 close 是 UI 初始化动作，不能误关应用级服务。
- `_round_reset_busy` 当前检查 CSV 线程集合。重录按钮当前隐藏，本次不开放重录功能，但保留入口和同路径覆盖保护。
- 产品录音的 OK/NG 标注只更新数据库，不改 WAV 路径；旧式录音标注可能移动 WAV。归档删除从 `ArchiveAudioDataDialog` 发起；串口异常轮次清理由录音服务延迟释放回调管理。CSV 文件保护必须补到这些实际入口，不能只替换导出线程。
- 完整基准记录 `tmp/full-csv-benchmark-20260922-105431/result.json` 已核对：600 秒、44.1 kHz、双通道、26,460,000 行，输出 1,162,232,136 字节；完整导出 80.5465089 秒，线程 CPU 77.859375 秒。该实验没有 GUI、分析负载。原始导出和基准导出 SHA256 同为 `facb5196b26f7ac36fdb470fe8850a89106fd94b7602164b40c24eeba38e5b65`。
- 前序局部实验：200 工况历史更新无 CSV 为 0.543 秒，CSV 线程并发为 4.632 秒，停止线程后为 0.551 秒；CSV 格式化只覆盖约 29.5 秒音频。它支持同进程竞争放大 GUI 延迟的推断，不是 600 秒导出计时，也不足以解释全部现场等待。
- 用户 GB18030 日志的一档：12:59:54.628 WAV 收尾；13:00:16.283 GUI 完成，`gui_publication=19.140` 秒；13:02:50.574 CSV 成功通知。下一档 WAV 创建于 13:00:42.568，GUI 启动通知于 13:00:46.404。文件名中的 13:00:23 不是实际采集起点。CSV 成功通知在 GUI 线程处理，不能直接等同子进程/线程内部发布时刻。
- `RecordingService` 使用 spawn、实例级状态和监督线程，`RecordingServiceBridge` 用 Qt queued connection 投递；分析服务也已有独立进程模式。复用职责划分，不复制录音硬件状态机。

需要新增计时确认的内容：CSV 内部实际起止、启动成本、排队时间、GUI 各收尾步骤及下一档实际采集启动延迟。CPU 和磁盘资源仍会共享。

## 3. 方案选择

| 方案 | 特点 | 决定 |
| --- | --- | --- |
| 单个常驻 CSV 子进程，顺序处理 | 避免每档 spawn；限制 CPU/磁盘并发；显式管理任务生命周期 | 采用 |
| 每份 CSV 创建子进程，串行运行 | 任务级进程清理简单，但每档重复启动和导入 | 不采用 |
| 多个 CSV 子进程/多 worker 进程池 | 可加快积压消化，但增加与录音、分析的资源竞争 | 不采用 |

服务在首次有效导出需求时启动专用 worker，随后复用到正常退出。进程启动、IPC、join 和文件清理在监督线程进行，GUI 只做小型状态预留与排队。CSV 开关关闭且没有旧任务时，不启动 worker。

## 4. 容量及录音准入

容量不变量：`已预留但尚未提交 + 排队 + 已派发且尚未确认释放 <= 16`，同时执行 CSV 的任务最多 1 个。终态结果已到但资源尚未释放的任务仍占容量；健康空闲 worker 不占任务容量。

- 开始一次需要 CSV 的产品录音前，原子取得一个预留 token；检查可用容量的方法没有副作用，反复刷新按钮不能重复预留。
- 预留发生在录音/播放硬件启动和工况推进等不可撤回副作用前。token 随录音上下文保存，包含本次 CSV 开关快照；启动后不因当前页面或开关变化撤销它。
- 录音成功并完成 WAV 元数据封装后，把同一个 token 转为导出任务，不再新增一个容量计数。失败、取消、校验不通过、启动前退出等没有可导出 WAV 的路径只释放一次 token。
- 正常录音流程提交时只构造路径、通道和归属快照，不传音频数组。已有预留不因服务进入正常关闭的 drain 阶段而被拒绝。
- 满额时禁止启动下一次需要 CSV 的录音，显示“原始 CSV 保存任务已满（16/16），请等待后重新触发”，保持 GUI 响应；不截断已开始的录音，不静默跳过 CSV，不阻止 WAV-only 录音或无 CSV 需求的校准。
- 容量恢复时刷新按钮/可用状态；不自动播放或录音。串口满额期间的触发沿用忙碌拒绝语义，并记录 CSV 满额原因，恢复后需要重新触发。其他入口的满额请求也不新增自动补录任务；既有其他原因的触发调度不作通用改造。
- 如在延迟启动期间容量变化，最终开始前再次原子预留；失败时撤销本次尚未执行的准备状态，不能推进工况或登记已开始。16 包含预留，不存在第 17 份隐含任务。
- 不按音频时长占多个名额。长档后连续短档可短暂积压；不把固定 600 秒间隔作为队列正确性的前提。

## 5. 组件、协议与状态

建议新增 `base/raw_audio_csv_protocol.py`、`base/raw_audio_csv_worker.py`、`base/raw_audio_csv_service.py`、`ui/raw_audio_csv_service_bridge.py`；名称在计划中固定，职责不可合并回巨大的 streaming mixin。

### 5.1 服务及 Qt 桥接

- 应用级一个服务实例，由启动入口创建并注入主窗口、sequence 和归档管理入口；独立启动 sequence/归档测试入口需显式提供所属服务或明确没有应用内活动 CSV。不创建隐藏全局 singleton，不让每个对话框各有一个 worker。
- 服务拥有容量、FIFO、token、任务索引、路径占用、worker generation、监督线程、控制 IPC 和关闭状态。Qt bridge 只负责 queued 投递和 GUI 订阅生命周期。
- 接口语义包括：无副作用的 capacity/busy 查询；原子 reserve；幂等 release_reservation；commit(token, immutable_request)；路径冲突查询/文件修改准入；异步 begin_shutdown 和 closed 通知。预留不是布尔状态，必须能追溯到具体录音。
- 任务终态仅一次。回调使用 task_id、worker generation 和原始记录归属；旧 worker、重复消息、过期窗口信号不能修改当前录音或重复释放容量。
- GUI 结果处理与路径释放分开：业务失败可先显示，未确认 worker 停止访问前不能开放删除或覆盖。服务状态推进不能依赖 GUI 消费结果，否则退出 drain 会死锁。

### 5.2 请求与事件

请求仅含协议版本、task_id、generation、规范化绝对 WAV/CSV/该任务临时文件路径、物理通道元组、录音 request_id 和小型归属标识。父进程保留轮次/记录快照；不传 QWidget、数据库对象、日志处理器或整段音频。

父进程保存待执行队列，只向子进程发送一个在途任务，避免出现无法统计的第二层任务队列。控制管道只发送 start/export/shutdown 与 ready/started/result/failure 这类小消息；低频进度若用于诊断必须限频，不能逐帧推送或形成无界日志队列。

任务状态：reserved → queued → dispatched/running → succeeded 或 failed → released。记录失败信息可早于 released；容量只在确认任务已无资源访问且清理流程完成后归还一次。临时文件删除失败可记录为残留，确认句柄释放后不无限扣留容量。

成功事件必须在导出函数返回（包含 WAV 关闭、CSV flush/fsync/close/replace）后发送；包含 task_id、generation、目标路径、worker PID、内部耗时、帧数/字节数。失败事件包含阶段、异常类型和有限长度描述，不复制任意大堆栈或音频数据。

### 5.3 Windows 和打包入口

- 明确使用 `multiprocessing.get_context("spawn")`，worker 为可导入模块顶层函数；不捕获 GUI self，不用嵌套 target。
- `main_window_Launcher.py` 已有 main guard 内的 freeze_support；验证它在 QApplication、服务创建和重型 UI 导入之前执行。直接 `main_window.py` 入口也必须在合适位置调用 freeze_support；所有实际发布入口遵守同一规则。
- worker 模块不得导入 UI、打开硬件、连接业务数据库或执行应用启动副作用。新进程及其 IPC 的创建均在监督线程；实例构造不得在模块导入时启动进程。
- 打包验证必须使用实际应用入口，确认新模块和 soundfile 依赖可用、没有递归启动窗口/进程、没有命令窗口闪出、中文及空格路径正常。当前未跟踪的 interval launcher 及其 spec 属于其他任务，不作为本次默认打包目标，不改动它们。

## 6. 文件内容、所有权与失败恢复

### 6.1 导出兼容性

复用现有 `export_raw_audio_csv` 的数据读取和格式化逻辑及默认 8192 帧，不换成另一种格式化实现。允许为任务专属临时路径增加可选内部接口，现有调用签名和默认行为保持兼容。

父进程为每个 task_id 生成目标目录下唯一临时路径并登记。worker 用排他创建，不能覆盖该路径上的已有文件。直接调用 exporter 的原有 mkstemp 路径仍受支持。这样在 worker 异常退出时父进程知道精确残留路径，无需扫描并删除其他 `.tmp` 文件。父进程不预读 WAV，不在 GUI 中创建目录、stat 大文件或 fsync。

父进程只清理已确认死亡 worker 对应任务的确切临时文件。不能删除 WAV、旧 CSV、其他运行或任务的临时文件。发布目标继续只通过同目录 os.replace 切换，任何异常不暴露部分 CSV。

### 6.2 文件修改协调

- queued 起到 released 为止占用源 WAV 和目标 CSV；路径标识按项目现有绝对路径/Windows 大小写规范统一；源和目标冲突检查使用同一规则。同一输出路径不得同时接纳两份任务。
- 提交与本轮文件归属登记发生在任务可被 worker 执行前；使用录音时保存的归属快照，不读取当前轮次。提交失败不登记不存在的成功结果；已登记的预期 CSV 可保持为该记录的待生成/失败文件，删除计数以实际存在文件为准。
- 用户发起的重置、删除、改名、移动或同路径重录，在冲突任务释放前明确拒绝并提示稍后重试，不取消 CSV。轮次重置保持已有“录音、分析、保存完成后可重置”的整体语义，busy 检查覆盖 reserved/queued/running/releasing。
- 产品 OK/NG 仅更新数据库且路径不变时，不因 CSV 读取占用额外阻塞；旧式标注实际移动路径的分支才检查 CSV 冲突。不能简单扩展 `_recording_path_is_leased` 导致所有标注被无条件阻止。
- 归档删除在用户确认后、实际删文件前重新取得修改许可。检查与提交必须互斥，避免先检查未占用、随后 worker 打开的竞态；修改许可覆盖源 WAV 和对应 CSV，操作结束或失败均释放。不依赖 Windows 恰好返回 PermissionError。
- 串口异常轮次的既有异步清理使用精确旧记录身份，等待录音和 CSV 两种占用都释放后才能执行；协调器保留释放后清理的优先权，不能让同路径新任务抢入。用户原操作不变，本次不扩展其删除范围；CSV 归属不能因 UI 清除而丢失。
- 服务只协调本应用的文件操作；外部程序移动/删除输入按导出失败处理，不尝试恢复或猜测新路径。

### 6.3 异常与 worker 重启

- 无效元数据、通道不匹配、输入丢失、磁盘满、权限问题、replace 失败均生成明确失败结果，WAV 保留，沿用“WAV 已保存，但原始 CSV 保存失败”的用户语义，不把 CSV 错误改成录音或分析失败。
- worker 正常任务异常在任务边界捕获并归一化，关闭句柄、清理临时文件后继续接受下一任务。不得回退为主进程 CSV 线程，不自动重试失败任务。
- 父进程同时监听终态消息和 worker 退出；进程已结束但无可信终态时，将当前任务记为 WorkerExit/结果未确认，记录退出码。即使目标 CSV 已经 replace 成功但消息丢失，也不能只凭文件存在宣称成功；保留完整目标文件，不覆盖重试。
- worker 死亡确认、IPC 回收、精确临时文件清理后，可以为下一份排队任务启动新 generation，最多仍有一个 CSV worker。启动/握手失败不循环重启：服务标记不可用，把尚未执行任务逐一明确报失败并释放；已在录音的预留在 WAV 完成时也明确报告 CSV 服务不可用。新的 CSV 录音准入关闭，应用重新启动后重新建立服务。
- 启动握手期限 30 秒；启动超时由监督线程终止并确认回收。已开始的真实导出不套用固定 80 秒/600 秒超时，避免误杀慢盘大文件。
- 如果无法确认子进程退出，则保持相关路径占用、停止派发，明确显示资源未释放；不能伪造 released 或悄悄启动第二个 worker。

## 7. 关闭与界面状态

- 主窗口正常关闭继续先遵守已有分析未完成的阻止规则。真正开始退出时关闭新录音准入，按已有录音策略完成取消/收尾，使所有预留最终转为任务或释放；CSV drain 覆盖这段期间晚到的合法提交。
- 正常退出等待已接纳 CSV 完成；通过 Qt 回调再次推进 close，不在 GUI 使用 join、pipe recv、processEvents 等同步等待循环。显示当前保存数量/等待退出状态，重复点击关闭幂等。分析/视频/录音既有关闭顺序可做必要接续，不扩展它们的行为。
- reserved、queued、running/releasing 清零后，发送 worker shutdown，监督线程确认进程退出并关闭 IPC/线程，才通知 closed。空闲 worker 关停给予 5 秒，超时可终止空闲进程并确认死亡；不为正常退出强制中断仍在导出的任务。
- 可见 sequence 窗口关闭同样异步等待其既有 CSV 保存完成，才关闭对应界面；应用级服务仍由应用生命周期管理。隐藏窗口初始化 close 不触发 drain 或永久关闭。主窗口退出时 sequence close 不重复建立关闭循环。
- aboutToQuit 仅做幂等兜底，不作为首次排空任务的入口；正常退出前 drain 必须已完成。系统强制结束/进程崩溃不保证 CSV 完成，不做本次未授权的持久化恢复。
- 不新增“处理中持续到 CSV 完成”的录音状态。录音 GUI 完成与 CSV 保存分别记录，CSV 不阻止已允许的自动分析入队或下一档录音。

## 8. 诊断与验收

### 8.1 分段计时

统一带录音 request_id、task_id、worker generation/PID、阶段和容量计数。父进程记录 reserve、submit、dispatch、ready、terminal_received、released；子进程记录 export_begin、export_end/failed，内部耗时使用同进程 monotonic/perf_counter。父进程另记排队和终态 Qt 投递延迟，不直接相减不同进程未校准的计时点。

在现有录音完成路径补少量分段计时：CSV 提交、最终波形投影、数据库保存、历史面板更新、自动分析入队、GUI 完成。下一档从有效启动请求计到 worker 实际采集启动/已有真实采集事件；GUI 收到 started 信号单列。禁止用文件名时间替代实际采集起点。日志不得逐采样点输出。

### 8.2 自动化功能验收

1. 小 WAV 覆盖单/双/非连续物理通道、跨块边界、空音频、中文和空格路径；新进程输出与原 exporter 逐字节一致，保留 BOM、LF、精度和全采样。源 WAV 不变。
2. 真正 Windows spawn 集成验证独立 PID、顺序复用同一健康 worker、开关关闭不创建任务/进程、主进程不调用逐样本导出、不经 IPC 发送整段音频。
3. 容量 16：冻结 worker，覆盖 1 执行 + 14 等待 + 1 录音预留；第 17 次预留拒绝，预留转提交总数不增加；失败/取消/重复回调无容量泄漏；释放一份后仅恢复一个名额。满额拒绝前不得启动硬件或推进工况。
4. 多个短录音排在长录音后，FIFO 排空；GUI 事件循环持续响应；满额触发不延后重放，容量恢复后新触发可用；CSV 容量限制仅作用于需要导出 CSV 的录音，不额外阻止仅保存 WAV 的录音及不导出 CSV 的校准操作。
5. 注入读写/replace 失败、worker 突然退出、成功发布后终态丢失、重复或过期消息、启动失败及关闭竞争；每任务最多一个终态、没有第二个同时写入的 worker、旧目标不被失败路径破坏。
6. 普通失败清理临时文件；异常退出父进程只清理精确归属临时文件；删除失败有诊断且不删除邻居文件。worker 死亡未确认时拒绝文件修改。
7. 排队期间删除、改名、覆盖、归档删除确认后的竞态、轮次重置、串口旧轮次清理、轮次切换后迟到回调均保持归属正确。数据库标签更新仍可用，隐藏重录功能不开放。
8. 主窗口/可见子窗口正常关闭、初始化隐藏 close、重复 close、late submit、worker 空闲/繁忙/异常退出均可验证；正常退出后无 CSV 子进程/监督线程/IPC 遗留，无 GUI 同步等待。

### 8.3 完整数据与并发性能验收

- 完整正确性使用现有 600 秒 WAV 和已有基准，不重复制造基线巨型 CSV。实施验证时只生成必要的新进程输出，校验 26,460,000 数据行、1,162,232,136 字节及上述 SHA256；记录输入标识、环境、耗时和结果。若现场文件不在测试机，使用经核对的相同 fixture；不得用几秒小样本声称通过完整验收。
- 在同机同数据、相同 200 工况界面、相同分析任务和下一档录音负载下，对照 CSV 关闭、原 CSV 线程、CSV 新子进程三组。完整 600 秒并发场景每组至少一次；固定较短的代表性 GUI 负载每组至少三次，交错顺序并区分首次 spawn 与复用。
- 记录 50ms Qt 心跳延迟 p50/p95/max、GUI 各收尾阶段、请求到实际采集启动、分析入队、CSV 自身总耗时及排队时间；同时记录 CPU/内存和负载差异。计时期间不以成功通知代替 worker 内部完成点。
- 功能硬门槛：格式全量一致；容量/文件/退出安全通过；录音无新增丢帧或长度错误；自动分析不因 CSV 迁移失败；满额时明确拒绝启动且 UI 不被冻结。
- 性能门槛：代表性 GUI 收尾的三次中位数相较线程组至少降低 30%；下一档实际采集启动延迟中位数不高于线程组中位数的 110% 加 100ms。Qt 心跳 p95 相较线程组不得恶化超过 20ms。完整场景必须呈现同方向的 GUI 改善，报告原始值；若线程组未复现明显竞争，记录“性能改善未验证”，不得凭 PID 改变宣称成功。
- 这些指标是本次迁移的验收目标，尚无进程版实测结果。CPU/磁盘负载导致不通过时先按新增分段计时定位；不得自动扩大到历史表格或间隔调度器改造，不以降低采样/精度绕过。

## 9. Compatibility / Migration

- Backward compatibility: required
- Protected surfaces: [CSV 开关及配置键、WAV 内容和元数据、CSV 路径/文件名/列名/物理通道顺序/编码/精度/全采样、原子发布、exporter 原有调用、数据库 schema、自动分析输入、标注及轮次文件归属、既有忙碌串口不补执行语义]
- Allowed breakage: [经用户同意新增总容量 16 的录音准入限制、忙碌文件修改明确拒绝、正常退出异步等待且状态可见]
- Migration strategy: none

不修改已有 CSV/WAV，不迁移数据库，不新增必须填写的用户配置；历史记录继续可读。16 作为明确容量合同，在适当 consts 模块定义供服务、UI 和测试共享；默认不增加用户调整界面。

## 10. 异常及全局状态约束

新增异常必须具有语义、诊断或恢复价值。预留满/关闭/路径忙属于明确返回状态，不用异常表达正常准入失败；元数据无效由边界校验报告；文件异常从 exporter 传播到 worker 任务边界归一化；IPC/进程异常由服务监督边界处理；Qt 只显示已归一化结果。

允许 worker 单任务边界和监督线程最外层捕获 Exception，以保证终态及资源释放诊断；必须记录任务和阶段，禁止静默吞错、无理由宽泛捕获、重复包裹已归一化错误或失败后偷偷回退线程。已有 exporter 临时删除失败的处理若用于新路径，需补充可观察残留诊断。

服务、队列、锁、进程、路径占用均为实例状态。禁止单次使用的模块级常量，稳定协议/文件格式/环境变量/CLI/API/schema/序列化状态边界除外；需要测试、文档、多模块稳定引用的常量放在项目合适的 consts 目录，否则局部变量或内联值。不得为了归档窗口访问创建全局可变任务注册表。
