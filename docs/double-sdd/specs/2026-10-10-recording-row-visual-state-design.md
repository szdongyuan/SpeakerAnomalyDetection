# 录制收尾工况行状态样式优化

## 需求与依据

用户已选择“固定 QSS、Qt 动态属性、只刷新变化的控件”的方案，并要求通过 writing-specs 流程修改。目标是消除录制收尾结果同步中的重复整表样式刷新，保持现有界面效果和业务行为。

设计基线：`e8d4b3bab29a2778faa18e64476cfbf37c7bf342`。

现有调用链：`_update_current_recent_session_result` → `_update_recent_session` → `_refresh_manual_product_condition_results_from_group` → 多次 `MotorResultPanel.set_condition_result` → 每次 `_refresh_row_styles` 遍历所有工况按钮并调用 `setStyleSheet`。

真实 Python/Qt 回调的离屏模拟已经复现：在 mark 模式下，200 个配置工况、100 个已完成工况、最近历史仍保留 20 条时，结果同步中位数约 4.468 秒。单次剖析中 `setStyleSheet` 占约 97.5%；仅在实验进程中合并整表样式刷新后约 0.070 秒。该结果证明此调用链存在性能问题，不能据此认定现场全部延迟都来自该路径；现场模式和完整配置尚未确认。

## 方案与范围

采用固定 QSS + 动态属性 + 定向刷新。这是用户确认的方向。另两种方案为：仅缓存每行样式字符串（改动较小，但仍需要防止全表扫描，状态与样式继续耦合）；仅批量合并整表刷新（能减少重复调用，但更新少量行时仍处理整张表）。两者不作为本次主方案。

主要修改 `ui/sequence/motor_result_panel.py`，共享 QSS 放入现有 `consts/ui_style_const.py`；补充对应 Qt 回归测试及可复现的性能验证脚本。业务组结果同步继续走现有入口，无需引入新业务缓存、异步发布或公开的批量接口。

本次优化工况行按钮及其结果标签。端口/轮次汇总、标题、详情表等其它样式不做整体重构；如果只是为了完整保留本次行状态转换而需要修改相关调用点，应保持窄范围。

## 状态与外观契约

### 工况按钮

按钮保留现有 `testTaskConditionButton` 对象名，以动态属性 `visualState` 表示最终视觉状态：

| 属性值 | 计算条件 | 原有颜色（背景 / 边框） | 悬停颜色（背景 / 边框） |
|---|---|---|---|
| `recording` | 当前行结果为“采集中” | `#EAF2FB / #2F80C9` | `#E3EEF9 / #286EAE` |
| `viewed` | 非采集中，且 key 等于 `viewed_key` | `#E1EFFF / #1877C9` | `#D7E9FC / #1269B2` |
| `normal` | 其余情况 | `#F4F8FC / #B8C8DA` | `#EDF4FC / #6FA8DC` |

保持 `recording > viewed > normal` 优先级、边框宽度、圆角、内边距、文字颜色及现有子标签布局。`selected_key` 和 `viewed_key` 语义不同，自动选择不得误用为用户查看高亮。继续使用 Qt `:hover`，不模拟鼠标事件状态，不把按钮改成 checkable。

### 结果标签

结果标签以独立动态属性 `resultTone` 表示现有样式归一化后的 `ok / ng / running / pending`。保持 OK 绿色、NG 红色、running 蓝色和其它状态的灰色，以及现有字体、字号、加粗、透明背景和无边框。未知 tone 的外观归一为 pending，但不擅自改写业务保存的 tone 或结果文本。属性/选择器要限定到该类工况标签，不能影响按钮内名称、进度或其它面板标签。

保持“数据保存中”等长文本对应的宽度调整，状态变化仍必须更新结果文字、进度和必要的布局。

## 刷新与生命周期契约

1. 固定 QSS 在面板或控件创建时安装一次；同一实例日常状态转换不重新设置行按钮/结果标签的样式表。可以使用面板内限定对象名的共享 QSS，不能每次修改父窗口或全局样式表。
2. 将样式状态更新与业务数据更新分离。只在最终动态属性值确实改变时设置属性并对目标控件执行局部样式重新计算和重绘；未变化的属性不得触发重新设置、polish/unpolish 或 update。初始化必须正确处理属性尚未设置的情况。
3. `set_condition_result` 普通更新仅触及目标行的样式状态，不为单行结果更新遍历全部行。不能为了跳过样式开销而跳过原有业务更新、判定保护、详情/汇总刷新或信号。
4. 用户查看切换仅同步旧、新查看行。相同选择仍保留原有点击/详情开合和信号语义，视觉状态未变化则无需样式刷新。
5. 自动准备采集/采集开始会清除 `viewed_key`，需要恢复旧查看行并更新目标行。跨端口的组合框信号可能同步重入端口刷新；重复到达同一状态不得造成重复 polish。维持现有自动选择、详情迁移和信号行为，不新增全局刷新。
6. 端口切换保持原有行显示/隐藏、当前选择和详情逻辑；仅当旧查看高亮被清除等视觉状态确有变化时刷新相关行。隐藏的采集行不能被错误清除采集状态。
7. 初始化、重置或配置重建允许一次 O(N) 的全行状态同步。重置清除查看高亮后必须再次准确同步受影响行，不能遗留 viewed 属性。重建只能引用当前仍存在的控件，不保留旧控件引用或跨面板状态。
8. 批量组结果同步可继续逐行调用既有接口，但样式操作数量应与真正变化的行数 D 成正比，消除 K 次结果更新 × N 行的样式操作。其它既有汇总计算可能仍有遍历，不宣称整条业务调用链已达到 O(D)。
9. Qt 动态属性变化不会被假定为自动完成样式重算；明确对变化的按钮或标签进行局部处理，并验证实际渲染。避免通过重设整个父面板 QSS 强制更新，也避免影响其它控件状态。

## Compatibility / Migration

- Backward compatibility: required。
- Protected surfaces: 现有面板公开方法、返回值、信号与触发时机，录制/重录/自动选择、手动查看、端口切换、模式切换、重置、配置重建、通道结果和失败保护，结果汇总、历史保留语义，界面配色/悬停/布局，数据库、配置、WAV/CSV 和进度文件格式。
- Allowed breakage: 无用户可见或公开接口破坏；允许替换内部样式生成与刷新辅助方法及只验证其实现细节的断言。
- Migration strategy: none；动态属性仅为当前控件的展示状态，不写入任何持久化文件。

## 验证与验收

### 行为与真实 Qt

- 在真实 Qt 控件上覆盖 normal、viewed、recording 的进入/退出及优先级，鼠标悬停、反复同状态通知、准备采集/采集自动选择、跨端口自动选择、查看切换及同一行重复点击。
- 覆盖 OK、NG、pending、running、未知 tone、长文本宽度，名称/进度标签不被误染色。
- 保留已有“待判定不能覆盖分析失败/结果不完整/已完成通道判定”等规则，并验证同步回调、信号和详情内容没有被性能短路跳过。
- 覆盖 reset、端口切换、配置全部重建及 preserve_results 刷新，旧查看行、隐藏行和新控件均无陈旧属性。
- 用渲染图或实际像素/调色板等能证明 QSS 生效的检查验证视觉状态，不能只断言属性字符串。保存必要的初始化/查看/采集/结果状态截图作为人工核查证据。

### 性能结构与对照

- 对行按钮及结果标签分别计数：已初始化控件的相同状态重复通知不再 setStyleSheet/setProperty/polish；一个普通行更新不会触发整表样式遍历，查看切换最多更新相关旧、新行。
- 以真实组同步调用链和真实控件复测 100/200 个工况、20/60/100 个已完成工况；最近历史限制维持 20，单独构造生产中跨录制保留的 completed keys，防止仅测历史数量而遗漏累积路径。
- 同一环境、同一输入顺序，基线与修改后分进程顺序执行；至少一次预热、三次测量，报告中位数、原始样本、样式调用计数及计时边界。比较实际行结果、tone、选择和汇总语义，不能用不执行结果同步的桩获得加速。
- 本机 200/100 场景的目标是相对真实基线显著降低回调耗时（参考目标至少 90%），同时满足结构性约束。CI 不采用机器相关的绝对秒数阈值；若对照达不到目标，应继续剖析并解释剩余开销，不能据临时实验的 70 ms 声称实现已达标。
- 动态属性版本要独立验证，先前“批量一次刷新”实验的数值不能冒充最终结果。测试模式作为分支对照，真实硬件、CSV/视频负载和现场总收尾时间不在模拟结论覆盖范围内。
- 执行相关工况面板、录制 GUI 收尾、手动工况循环、自动分析结果应用、配置刷新与重置测试；如有失败，先判断是否基线已有问题，不能削弱断言来掩盖回归。

## 实施约束

不启动或停止用户采集进程，不读写真实业务数据库或录音，不修改采集线程、文件关闭和分析算法。所有样式修改仍在 Qt GUI 线程执行，不引入定时器、后台渲染线程、全局缓存或自定义 Qt 样式引擎。

状态尽量直接保存在现有控件动态属性/面板实例中，不增加另一份业务状态真相。共享样式遵循现有 consts 样式组织；禁止为单一调用引入无必要的模块全局常量，稳定的公共样式/属性边界除外。

保持现有无效工况的返回行为。新异常仅限有明确语义、诊断或恢复价值的边界；不添加吞掉 Qt 刷新错误的 broad catch、不静默退回整表 setStyleSheet、不做重复防御包装。不要改动与此次行样式优化无关的功能。

最终交付经验证的本地修改及性能证据；没有发布、推送或永久提交授权。设计与实施阶段的临时检查点由本工作流结束时按记录的基线清理，并保留最终文件内容。
