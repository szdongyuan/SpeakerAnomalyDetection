# 录制收尾：整段峰谷摘要替代主进程全量回读

## 目标与已选方向

在现有 `codex/recording-final-envelope` 工作树继续设计。用户要求录制期间累计整段峰谷，结束后直接显示完整波形，降低本地收尾耗时及内存。用户在推荐方案讨论后要求继续；本规格采用推荐方向：主录制取消全量 WAV 样本回读及 SHA-256 比对，不增加后台全量比对。

主录制指 `RecordingRequest.purpose == "main"`，包括声卡和 VE 输入、开启或关闭实时预览的情况。其他 purpose、旧的非进程录制路径及独立分析任务不改用此协议。

本规格已通过规格审查，用户已同意继续进入实施计划；这不代表峰谷功能已经实现。已完成的隐藏全局 OK/NG 删除作为当前工作树前置变更保留，参见 `2026-10-12-retire-hidden-manual-label-design.md`；该旧入口不再构成完整音频数组的兼容要求。

成功标准：正常主录制结束后，录制子进程完成必要文件收尾，主进程仅接收有界显示摘要并发布波形；不为收尾构造长度为整段样本数的多通道/单声道数组，不再为收尾读取 WAV data 区。文件关闭、必要元数据、数据库及后续分析仍有各自耗时，不承诺收尾为零或固定秒数。

## 当前实现与方案比较

- `base/recording_capture.py` 在 `_consume_block` 写入裁剪后的数据，writer 返回实际保存的 float32 量化样本。当前每块计算样本摘要；`_finish_audio` 检查接收/消费/写入帧数、WAV 头、元数据及资源释放。
- `base/recording_result_reader.py` 的 `ResultReader` 在父进程重新读取全部 WAV，计算 SHA-256、单声道、质量指标和显示波形。`RecordingAudio.is_prepared_for` 绑定完整数组与冻结请求。
- `base/recording_service.py` 目前在 completed 事件后启动 reader；GUI 在 accepted 和 released 后才发布结果。
- `ui/sequence/sequence_widget_recording_process_ops.py` 和 `sequence_widget_streaming_ops.py` 的完成逻辑依赖完整数组形状；不能只删 reader 或传入空数组。
- 实时预览默认可只保留最近 10 秒，每通道 4,000 点；最终显示上限为 48,000 点。预览流具有丢帧/ACK 机制，不适合承担最终整段结果。

选用独立的、固定分桶的最终摘要：目标帧数在请求中已确定，可匹配现有离线显示算法，内存固定，且不依赖预览是否开启。复用实时预览会丢失历史或降低最终分辨率；后台全量比对仍会产生完整读取和磁盘竞争，因此不采用这两种方案。

## 数据流与责任边界

`采集队列 → 消费线程 → 裁剪 → WAV writer → 已量化样本 → 峰谷累计 + 质量统计 → 文件关闭及基本检查 → completed 摘要 → 父进程协议校验 → accepted/released → GUI 发布`

1. 新增 Qt 无关的最终摘要累计器，例如 `base/recording_final_envelope.py`。它只持有固定容量 NumPy 数组和当前分桶状态，生命周期属于一次录制请求。
2. `RecordingCapture` 为 main 请求创建累计器，独立于 `_preview_enabled`。在消费线程收到 writer 成功返回的 `quantized` 后处理；不能在硬件回调线程中进行摘要计算，不能使用裁剪前或量化前的预览数据。
3. main 不再计算或要求样本 digest。其他 purpose 的原有 digest、reader 及 `RecordingAudio` 契约保留。
4. 子进程完成计数、质量和文件检查后，使用原有 completed 可靠控制事件一次性携带最终摘要。禁止放入可覆盖的实时预览队列；禁止另外发送完整音频。
5. 父进程 service 对 main 分支直接构造专用的已验证显示结果，不创建 `ResultReader`；其他 purpose 保留 reader 路径。新的结果类型不伪装成 `RecordingAudio`，不伪造 `multi`/`mono` 空数组。
6. GUI 增加专用主录制摘要发布入口。必要时从 `_on_streaming_complete` 抽取局部共用的文件发布/后续业务部分，保留旧数组路径；不改造全部录制架构。

## 整段峰谷算法

令 P 为现有最终点数上限 48,000，T 为目标原始帧数。有效裁剪 S 沿用现有规则：仅 main 裁剪，若 trim >= T 则 S=0，并保留现有警告。最终 N=T-S，时间零点对应裁剪后的首个样本。

- N<=P：保留至多 P 个量化样本，输出全部点；这是有界的小录音显示数据，不扩展为整段音频缓存。
- N>P：桶数预算 B=floor((P-2)/2)=23,999；桶宽 W=ceil(N/B)。按全局裁剪后采样位置分桶，消费块边界不影响桶边界。
- 每桶每通道保存 min/max 的 float32 幅值及 int64 全局位置。同值选择最早位置，与 `argmin/argmax` 的现有行为一致。
- 保留首点、末点；桶内按采样位置排列峰谷；输出时去除重复采样位置。最后不满桶也必须纳入。每通道点数<=P。
- 输出为按请求物理通道顺序排列的 int64 采样位置和 float32 幅值；父进程从位置生成 float64 时间轴 `index / sample_rate`，避免传输重复时间轴。
- 一次追加只处理当前块和桶统计，不保存历史块、不逐样本创建 Python 对象、不在收尾重新扫描原始样本。
- 最终输出应与 `prepare_waveform_display_data` 处理相同有限值量化样本的结果一致，包含峰谷顺序、短录音、首尾和尾桶。最终显示是概要，放大后不会恢复所有原始样本细节；数值分析仍使用 WAV。

## 保留的检查与取消的保障

保留子进程：接收帧数=消费帧数=目标帧数；写入帧数=N；writer/stream 关闭结果；WAV 头的 PCM24、采样率、通道数及帧数；元数据追加后的文件结构检查；VE 必需校准元数据和冻结配置一致性；所有文件句柄释放及临时文件清理规则。

同时迁移 `ResultReader._validate_metadata` 对普通声卡的既有检查：只要 metadata_appended=True，子进程就必须回读校准元数据，使用与旧reader相同的规范化方式与冻结请求比较，并确认读取句柄全部释放。读取状态无效、内容不匹配或句柄未释放均不可成功；不能只检查WAV头。普通声卡追加失败但回滚成功且文件仍有效时，继续沿用 metadata_appended=False 的警告行为。VE仍要求成功追加、正确backend和内容一致。这些仅涉及结构/元数据读取，不读取整段音频data区。

主录制质量检查从 reader 移至消费线程累计：按保存样本计算单声道 peak、RMS、variance，结束时使用当前冻结阈值及原有失败提示。不能仅从峰谷点近似这些指标。普通声卡维持量化样本 float32 通道均值；VE 保持“先各通道除以 range_max，再求 float32 通道均值”的原有顺序，同时保留 VE 保存样本及实际电压单声道的有限值检查。

统计状态为计数、绝对峰值、float64 平方和，以及稳定的分块均值/M2 合并状态；方差为总体方差 M2/count。RMS 使用平方和/count。保留 enabled 开关和比较方向，不新增宽松容差来放行不合格录音。流式与批量浮点归约可能有舍入差异，应测试阈值附近案例，并记录该数值差异，而不宣称逐位相等。非有限值处理不得导致异常音频绕过原有 VE 检查；普通声卡遵循现有 writer 的输入处理规则，摘要不得引入额外裁剪或增益。

父进程保留请求身份、generation、路径、通道顺序、计数、状态、释放证据及摘要结构校验；取消的是父进程重新打开 WAV 做收尾校验，不是取消进程协议校验。

取消的保障：不再通过重新读取落盘的全部样本，证明其 SHA-256 与写入侧一致。计数、文件头和成功关闭不能保证磁盘样本逐字节一致，也不能发现所有存储损坏；峰谷摘要也不能替代完整性校验。不添加后台全量读取来暗中恢复旧开销。

## 完成协议与生命周期

在 `base/recording_process_protocol.py` 定义有界的最终显示 payload，并以具名可选字段扩展 `RecordingResult`；新增字段放在现有默认字段之后，避免破坏其他 purpose 的位置参数调用。main 必须提供新完成证据；没有摘要证据的旧 main 消息被明确拒绝，禁止静默降级到 reader。应用内父子进程随同一次发布升级，不支持跨版本 main 协议混用。

payload 至少包含版本、N、请求通道序列，以及“有效各通道摘要”或“明确的显示生成错误”。正常结果每个通道数组为一维、长度相等、位置严格递增、范围[0,N)，包含0和N-1，数量<=P。main 的成功表示子进程质量门已通过且基本检查结束；禁用质量检查时应明确标识 skipped，不能假称已检查。必要的质量统计证据及状态固定大小，并与冻结请求匹配。

父进程在 service 所属后台线程完成 O(C×P) 的结构检查、时间轴构造及只读所有权包装；反序列化后的数组不能仅凭 frozen dataclass 视为不可变。GUI 只检查与请求/已验证对象的绑定及窗口对应关系，不再次扫描整段数据或在 GUI 线程做昂贵数组工作。

沿用 result_ready → accept/reject → accepted → released 的业务顺序及路径租约。main 没有 reader 时，从未占有 reader 文件句柄，可标记对应释放条件满足；仍需等待子进程及清理释放。拒绝、取消、超时、工作进程死亡和旧 generation 消息继续走原有终态处理，不能发布两次、提前释放路径或在租约释放前移动/重命名 WAV。VE 可重叠的采集/收尾槽位规则不变，不能全局缓存或复用上一轮摘要。

## UI、分析及文件兼容

成功接受并释放主录制后，先原子更新已保存录音来源（请求身份、路径、采样率、真实最终帧数、校准来源），清除旧 `store_wave_data` / `store_wave_data_multi` 为 None，再发布显示。禁止把峰谷幅值填入这些原始数据字段。`audio_lenth` 使用 N，不使用显示点数。无效或取消的新录制不覆盖上一份已发布来源；显示失败并不等于新录制无效，此时已保存录音来源仍属于新WAV，后续数据库、CSV和分析使用它。

显示来源与已保存录音来源分别记录。各通道开始刷新前，目标条件的最终显示标识失效；只有所有目标通道绘图成功后，才将显示来源绑定新请求并标为整段完成。若子进程生成摘要失败或任意通道绘图抛错，现有绘图事务先回滚部分更新，再统一隐藏该条件的旧/部分曲线，显示“波形刷新失败”占位；不把回滚后的旧曲线配上新WAV路径继续展示。失败条件没有可用的最终显示来源，也不保留可误操作的曲线交互。其他已完成条件不受影响，已保存录音来源仍保留新请求身份、N和校准信息。

`_clear_unpublished_recording_source` 当前以原始数组是否为 None 判断是否存在旧音频，需要改为显式的已发布来源身份；不能在新录制取消时清除上一份无原始数组但仍有效的 WAV/校准来源。

当前手动、自动分析入口在 `sequence_widget_analysis_process_ops.py` 按条件记录的 WAV 路径构建独立分析任务，保留。CSV 导出仍从 WAV 路径交给自己的后台流程；条件缓存、历史、数据库保存、标记改名、条码、串口档位和下一轮启动保持原有顺序和规则。独立分析、导出或用户主动查看原始数据所需的 WAV 读取不属于被取消的收尾回读。

`signal_analysis_window.py` / `reference_spectrum_analysis_window.py` 等旧数组消费者不接收峰谷冒充的原始数据，也不在本次恢复不可达的旧入口。当前主界面入口必须通过已有文件分析路径正常工作；旧非进程流程及其原始数组契约保持原样。实现验证必须覆盖现有可见分析入口，不能依赖这两个字段被主录制自动填充。

实时预览继续保持当前累计/最近10秒模式、4,000点上限及刷新频率，最终摘要在预览关闭、预览故障或预览消息丢弃时仍需独立覆盖整段。

## 失败处理

- 写入、计数、质量、必要元数据或资源释放错误属于录制失败，沿用既有失败/清理边界，不发布成功摘要。
- 最终峰谷生成或 Qt 绘图错误属于显示失败，不把已成功保存的 WAV 判成录制损坏。累计器错误在明确的显示边界记录一次并停止本轮累计，终态带显式错误；主进程提示“录音已保存，但波形刷新失败”。按前述显示事务隐藏目标条件的旧/部分曲线并清除显示来源；后续保存、分析仍按新文件执行。
- 正常 payload 类型、维度、点数、通道或索引不合法是协议错误，应拒绝，不伪装成显示警告；明确的显示错误状态与损坏 payload 要区分。
- 不为显示失败全量回读 WAV；不添加无日志的兜底或无操作兼容方法。

## 内存与性能预算

5 通道长录音，按每通道最多23,999桶、每桶两组(float32幅值,int64位置)计算，摘要主体约2.88 MB；最终(int64位置,float32幅值)约2.88 MB；父进程(time float64,幅值float32)约2.88 MB。

前面给出的5–10 MB是单份累计/输出的粗略预算，不能当作跨进程总峰值保证。序列化、父子暂时并存、反序列化、只读包装、GUI及绘图库复制都会增加峰值。实现应及时释放中间所有权，数据工作集随显示点数和通道数有界，并测量父/子进程及总峰值；不能宣称总新增内存必定不超过10 MB。

针对5通道、44.1kHz、600秒场景，原完整float32 multi+mono约635 MB（十进制），新完成结果不应分配这两份数组。既有采集队列、实时预览、CSV及分析的内存单独列出，不计作峰谷“零成本”。

日志记录摘要累计总耗时、结束物化耗时、IPC传递/父进程准备、GUI发布、target到完成耗时；main 不应再产生实际 `read_validation` 全量读阶段。保留现有日志关联request与阶段，不能把不同进程时钟直接混算。

## Compatibility / Migration

- Backward compatibility: partial。
- Protected surfaces: WAV PCM24 内容/布局、校准元数据、文件名和数据库结构、原有配置、预览模式、当前主界面功能、质量阈值语义、取消/租约/自动分析流程、其他purpose的reader行为。
- Allowed breakage: main 内部完成对象不再携带完整数组或全量样本digest；main不再自动填充全长内存缓存；取消落盘全样本摘要比对。旧隐藏全局OK/NG已独立删除，不恢复。
- Migration strategy: 无用户数据迁移、无新配置开关；父子内部协议同时升级并明确校验新payload。保留旧reader仅服务非main及其既有直接调用，不给main静默兼容回读。

## 代码纪律

异常只在输入/协议校验、文件/进程资源边界、统计门或明确显示边界产生和归一化。每个新增异常必须对应可诊断的不变量或恢复行为；禁止对已验证普通计算叠加宽泛catch、重复兜底或吞错。借用已有资源终态边界，不能因为显示错误更改文件释放责任。

状态归请求/实例所有，不新增可变全局。复用现有最终显示点数常量。仅使用一次的值置于局部；协议版本/序列化字段等稳定边界可按仓库常量约定定义，跨模块共享常量放入合适consts模块。只做本方案需要的定向拆分。

## 验证与验收

1. 算法：随机分块、跨桶、单点脉冲、负峰、等值、短录音、尾桶、裁剪跨块、trim>=target、稀疏物理通道及顺序；与现有批量显示算法对比，峰谷幅值/位置相同，每通道<=48,000点，首末时间准确。
2. 质量：流式和当前批量门对静音、常量、弱信号、正常信号、通道抵消、阈值附近、enabled=false及VE归一化次序对比；检查非有限值、float32均值溢出等现有保护不被移除。
3. 无回读：main的测试注入会报错的reader_factory，确认从不调用；对子进程只允许头/元数据检查，禁止样本read；独立测试其他purpose仍调用原reader并校验digest。不能仅用耗时证明没有回读。
4. 生命周期：结果成功/拒绝/取消、晚到结果、重复终态、旧generation、关闭失败、元数据失败、显示失败、租约释放前后改名、下一档录制与上一档收尾并行；无错轮发布和双重清理。声卡已追加元数据的内容不匹配/无效状态/读取关闭失败必须失败；声卡未追加的可恢复警告与VE必需元数据行为分别覆盖。
5. UI：Qt offscreen覆盖无multi/mono的完成发布、真实N、5通道整段刷新、预览关闭/滚动模式、原子录音来源更新、新录制取消保留旧来源、数据库/CSV/自动分析入队、当前手动分析入口和条码/串口流程。特别注入第二通道绘图失败，验证没有混合新旧通道显示：目标条件显示不可用且无显示来源，录音来源/N/校准绑定新文件，CSV和分析仍接收新路径，其他条件保持原样；摘要生成失败也须覆盖相同终态。
6. 本地模拟：用合成的5通道44.1kHz数据按实际块大小走消费/收尾，至少比较短/600秒录音；模拟不需真实等待600秒，也不连网络共享、不改生产录音。报告原路径与新路径的墙钟、CPU、各阶段和父子峰值；把CSV/独立分析从收尾路径指标分开，同时说明启用时仍可能竞争磁盘。
7. 回归：覆盖现有recording_capture/finalization/service/pipeline/storage/metadata/audio_lifetime，以及GUI finalization/process integration/analysis route/raw CSV/multichannel/VE测试；按影响执行，不以删除既有行为断言来凑通过。

当前工作树已知工具栏测试存在4个基线失败（fixture缺少active_product_program_file及3个offscreen绘图断言）。报告并区分，不把它们误归于本方案，也不借本方案顺手修复无关代码。
